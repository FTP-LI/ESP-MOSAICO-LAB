# ESP-Mosaico V1.2 游戏机套件文件规划

本套件面向 ESP-Mosaico CoreBoard V1.2，采用外接按键扩展板，先做纵向掌机并保留横向方案，复用主机屏幕、电池、扬声器和振动马达，属于 ESP-MOSAICO-LAB 的非官方扩展。采用仓库现有的分类结构：套件总入口放在本目录，控制板与掌机结构件放在 `hardware/`，游戏固件放在 `firmware/`。

当前状态为 `experimental`，阶段为板级诊断与电气原型。已建立 [诊断固件](../../firmware/game-console/README.md)、[ESP-IDF 环境](../../tools/esp-idf/README.md) 和 [9 键 H2 原理图草案](../../hardware/gamepad-board/rev-0.1/README.md)。两种配置编译通过，[原理图严格 DRC 已通过](../../hardware/gamepad-board/rev-0.1/checks/2026-10-19-drc.md)；尚未烧录、打样或进行实测，连接器配合与器件封装待确认。更新日期：2026-10-19（Asia/Shanghai）。

开始开发时先看 [快速开始](quick-start.md)，完成工程获取、构建检查和联调准备；功能范围与并行安排见 [首轮需求与并行开发](requirements.md)。硬件制作按键原型，软件先跑显示、声音和游戏原型，通过统一逻辑按键约定联调。

游戏方向已确定为运行现成的 FC、GB 与 PICO-8 游戏。优先评估 Retro-Go 的 FC／GB 路线，再加入 PICO-8 兼容运行时；候选证据、移植缺口和固件目录调整见 [复古游戏运行方案](emulation-plan.md)。运行平台与具体游戏兼容性尚未验证。

已确认的范围是外接控制器、结构件及配套软件。十字键和 A/B 采用硅胶导电胶方向，键帽、支点、限位与壳体需要同步验证。显示和电源使用主机现有系统；不规划新增屏幕、电池或充电模块。具体布局、弯排针连接路径、结构测量和软件并行任务见 [纵向与横向掌机方案](form-factor.md)。该方案已建档，尺寸图和 CAD 尚未建立。

## 项目边界与标识

| 标识 | 规划位置 | 管理范围 |
| --- | --- | --- |
| `game-console-kit` | `docs/game-console-kit/` | 套件需求、整体方案、跨模块装配及整机验收 |
| `gamepad-board` | `hardware/gamepad-board/` | 自研控制板的电路、板框、器件、制造和板级测试 |
| `gamepad-enclosure` | `hardware/gamepad-enclosure/` | 掌机壳体、握把、按键帽、硅胶胶垫与固定件的配合；取得实际结构数据后建立目录 |
| `game-console` | `firmware/game-console/` | 运行于主机的模拟器、卡带运行时、菜单、输入与存档管理 |

主机已有资料继续由 [esp-mosaico](../../hardware/esp-mosaico/README.md) 管理；套件通过链接引用，避免复制原始 PDF、引脚表或关键器件表。如果方案需要独立控制 MCU，其固件再单独建立项目，不预先假设控制板必须带 MCU。

控制板与外壳可以独立改版，分别记录修订号和配合关系。若最终采用两块不同的左右控制板，应为每块板建立独立板卡标识及 README；只是一块板的不同装配选项时，在该板 BOM 和装配说明中记录。

`tools/esp-idf/` 已保存环境激活脚本，`tools/check-gamepad.py` 核对原理图和固件映射。有独立资源转换工具或游戏示例时，再按用途加入目录。单纯记录测试步骤不需要新建自动化项目。

## 关键文件写什么

| 文件 | 必须承载的信息 | 使用关系 |
| --- | --- | --- |
| `requirements.md` | 记录已确定的外接手柄形态与主机屏幕、电池复用；明确按键数量与布局、游戏范围、音频需求、安装方式、供电目标、性能指标及验收方法 | 硬件、结构和固件共同依据 |
| `form-factor.md` | 纵向优先、横向保留的布局；弯排针接入路径；硅胶胶垫、键帽、支点与触点配合；板载声音/振动及待测尺寸 | 已建立的结构方向依据，不作为制造图 |
| 套件 `architecture.md` | 主机、控制板、外壳和固件的分工；接口选择、资源冲突及决策原因；需要互相匹配的修订版 | 汇总方案，链接各专业文件 |
| 板级 `interfaces.md` | 连接器针号和观察方向、电源输入输出方向、电压与逻辑电平、负载预算及来源 | 电气连接定义的主入口 |
| `pin-map.csv` | 连接器、针号、信号名、方向、电源域、板上网络或器件、主机 GPIO 或总线、依据、确认状态 | 电路与固件核对用；未确认字段写待确认，不猜引脚 |
| `dimensions.md` | 控制板、连接器及与主机配合部位的尺寸来源、测量基准、按键行程、开孔与装配间隙 | 手柄结构模型与板框的配合依据 |
| `board-mapping.md` | 适用板卡修订、物理按键到逻辑动作的映射、输入极性和去抖方案；链接板级定义与代码配置 | 不再维护一份独立的电气针号表；数值与代码保持一致 |
| 套件 `assembly.md` | 各模块及修订、整套物料数量、装配顺序、连接方向和照片 | 引用板级和结构装配说明，避免复制细节 |
| `test-plan.md` | 输入与组合键、显示、声音、游戏运行、功耗和装配等适用测试的步骤、指标与通过标准 | 测试计划与实际结果分开保存 |

硬件选型前先核对现有 [左右接口说明](../../hardware/esp-mosaico/rev-1.2/interfaces.md) 与 [设计分析](../../hardware/esp-mosaico/rev-1.2/design-analysis.md)，把音频、调试与扩展功能的资源使用情况写入方案。BaseBoard 实物版本、连接器方向及供电能力仍需确认；连接方式确认前，相关设计文件必须标注“不可按此接线”。

结构设计保存可编辑模型，导出的 STL 或 STEP 与源模型一起记录修订。主机原有 [components.csv](../../hardware/esp-mosaico/rev-1.2/components.csv) 仅是关键器件摘录，不能直接作为套件采购 BOM；套件清单也不替代控制板的位号 BOM。

## 按阶段建立文件

| 阶段 | 建立或更新的文件 | 完成条件 |
| --- | --- | --- |
| 0 文件规划 | 本 README、根目录入口、变更记录 | 路径职责清楚，未来文件与当前文件明确区分 |
| 1 需求与方案 | `requirements.md`、套件 `architecture.md`、`test-plan.md`；启动实际子项目时建立各自 README | 在已确认形态下，确定按键、单板或分体布局、游戏范围、接口及工具链，记录待验证假设 |
| 2 接口与结构验证 | 控制板 `interfaces.md`、`pin-map.csv`；依据 `form-factor.md` 测量并建立 `dimensions.md` 与结构样件；固件完善输入和振动诊断 | 核对实物版本、方向和尺寸，验证硅胶按键配合，使硬件、结构与固件有共同依据 |
| 3 设计与打样 | `eda/`、`bom.csv`、`exports/`、`manufacturing/`、`design-review.md` 和板级装配说明 | 按仓库规范完成打样前资料及设计检查，源文件和制造输出对应同一修订 |
| 4 联调与游戏兼容 | 模拟器适配、游戏兼容性表、构建烧录说明、软件测试和板级测试记录 | 按运行方案依次验证 FC／GB、存储与存档、PICO-8，记录逐游戏结果 |
| 5 套件交付 | 套件 `assembly.md`、`user-guide.md`、整机测试记录、兼容性索引及发布说明 | 明确可用的主机、板卡、外壳和固件组合；保留构建及制造文件来源 |

此表按资料成熟度分类，不要求先完成硬件再开始软件；执行顺序以 [并行开发安排](requirements.md) 为准。设计检查、打样和设备实测分别记录。测试记录从 [现有模板](../templates/test-record.md) 创建，设计检查使用 [硬件检查模板](../templates/hardware-review.md)。没有执行的项目标为“未执行”，不能因建立文件或成功构建就改为 `verified`。

## 版本与文件管理

- `V1.2` 指目标主机；`gamepad-board/rev-0.1` 与外壳 `rev-0.1` 是拟采用的首版自研设计编号，彼此独立，也不等于仓库发布版本。
- 板卡和外壳按各自修订保存，兼容关系在套件方案、项目 README 与发布说明中明确；实际验证组合记入 [兼容性索引](../compatibility.md)。固件沿用 Git 提交和仓库发布标签，不按硬件修订复制整套源码。
- 设计工具版本写入项目 README。可编辑源文件、项目专用库、制造输出与实际资源进入版本控制；缓存、自动备份、临时日志和构建二进制沿用现有忽略规则。
- 实测记录建议命名为 `YYYY-MM-DD-<test-name>.md`，关联完整源码提交、主机版本、板卡和外壳修订、固件标识及测量条件；必要的脱敏日志与照片放在同名证据目录并链接。无需修改忽略规则来保留所有运行日志。
- 第三方器件资料在对应项目登记来源、版本和许可；已有主机归档直接引用。游戏、字体、图像、音频和外部代码分别记录来源与许可，引入时确定适用范围。
- 新增硬件设计、固件源码和资源的许可范围在各项目 README 中明确。本规划文档沿用仓库现有 [LICENSE](../../LICENSE)。

下一步是连接设备完成板载诊断，同时核对 BaseBoard 与 H2 的实物方向及按键纸样；电气条件确认后联调 9 键原型，再接入首款测试游戏。仓库维护遵循 [REPOSITORY_GUIDELINES.md](../../REPOSITORY_GUIDELINES.md)，返回 [仓库首页](../../README.md)。
