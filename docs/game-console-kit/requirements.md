# 游戏机套件首轮需求与并行开发

硬件与软件从同一份功能范围和逻辑按键约定开始，分别制作按键原型与主机软件原型，再做实物联调。建议首轮共同目标是：用外接实体按键操作一款 FC 测试游戏，显示和声音正常，能够暂停并返回菜单。该目标是首轮验收建议，不是已完成结果。

日期：2026-10-19（Asia/Shanghai）。状态：`experimental`，板级诊断与电气原型。已建立 [9 键 GPIO 原理图草案](../../hardware/gamepad-board/rev-0.1/README.md) 和 [诊断固件](../../firmware/game-console/README.md)，软件构建通过、实机未测。总体文件归属见 [文件规划](README.md)，模拟器候选和依据见 [运行方案](emulation-plan.md)。

## 两边先共用的输入约定

这部分约定逻辑动作，不指定 GPIO、连接器针号、通信芯片或总线地址。电气方案确定后，硬件定义放入板级 `interfaces.md` 和 `pin-map.csv`，固件在 `board-mapping.md` 中引用它们。

| 约定项 | 首轮建议 |
| --- | --- |
| 逻辑动作 | `UP`、`DOWN`、`LEFT`、`RIGHT`、`A`、`B`、`START`、`SELECT`、`MENU` |
| 状态含义 | 按下为 1、松开为 0；逻辑状态与引脚高低电平分开 |
| 同时按键 | 状态应表达多个按键同时按下，至少覆盖斜向加 A／B；不能只返回最后一个键 |
| 去抖 | 原始输入适配层处理；模拟器接收稳定状态，参数通过实际开关测试确定 |
| 菜单动作 | 独立按键或组合键由布局方案确定；组合键须定义触发、消费和释放规则，避免误操作游戏 |
| 输入异常 | 驱动有有界超时；异常时上报不可用并释放旧按键状态，避免持续移动 |
| 测试输入 | 触摸或测试事件转换成相同逻辑状态；进入真实输入模式时清空旧状态 |

软件先实现这组动作到模拟器的映射，硬件选型只影响产生这些动作的适配层。键位可以先在屏幕诊断页显示，控制板接入后沿用同一诊断流程验证。

## 并行推进与汇合点

以下按工作轮次组织，不承诺固定工期。硬件不必等完整模拟器移植完成，软件也不必等 PCB 到货。

| 轮次 | 硬件线 | 软件线 | 共同验收或决策 |
| --- | --- | --- | --- |
| 0 确认基线 | 登记底板版本、连接器方向和配合尺寸；制作纸面按键布局；列出需保留的音频与调试资源 | 确认并加载 ESP-IDF；选择支持目标芯片的 BSP 基准；记录现有设备固件及恢复入口 | 逻辑按键约定成立；形成待核实的实物与资源清单 |
| 1 各自原型 | 根据可用引脚比较直连 GPIO 与 I2C 扩展方案；核对电平、上拉和供电后搭建按键验证板 | 先跑通显示、测试音和输入诊断；以测试输入接入一款 FC 游戏；另行验证存储读写 | 按键方案能够输出完整状态，软件能够独立运行测试场景 |
| 2 实物汇合 | 连接按键原型，核对单键、组合键及干扰；调整按键位置和固定方式 | 将真实输入驱动接入相同逻辑动作；验证游戏、暂停、音频和退出流程 | 实体按键实际控制游戏，问题记录可复现 |
| 3 设计冻结 | 确认连接器、板框、孔位、器件封装、按键布局及是否加入 microSD；完成设计检查与制造资料 | 固定板级映射、构建基准和诊断固件；持续推进 GB、菜单与存档 | 电气、结构和存储决策明确后进入打样；不以完整软件功能作为打样前提 |
| 4 样板回归 | 验证样板与原型的一致性，检查供电、装配和操作手感 | 在样板上复测输入、游戏、声音、保存和恢复，记录性能与内存 | 更新实际测试记录和兼容性，确定下一修订内容 |

首轮电气原型已选 H2 的 9 路 GPIO 直连，I²C 扩展留作后续键数或接口需求变化时的备选。具体电路和布局以 [按键板接口说明](../../hardware/gamepad-board/rev-0.1/interfaces.md) 为准。连接器方向、电平与供电尚未确认，**不可按此接线**。

## 第一轮通过标准

以下均为建议的验证要求，当前状态全部为“未执行”。测试游戏、固件提交、主机版本、供电、亮度、音量和输入方案应随记录保存。

| 检查项 | 首轮通过条件 |
| --- | --- |
| 输入诊断 | 各逻辑键按下与松开正确；斜向加动作键正确；松手后无残留按键状态 |
| 游戏控制 | 实体按键能够完成所选 FC 测试游戏的一段约定操作；菜单、暂停和退出行为明确 |
| 画面与声音 | 画面比例符合设置，操作时声音持续；没有持续可感知的音画错位或反复音频中断 |
| 持续运行 | 建议连续运行 10 分钟，记录运行速度、显示帧时间、音频异常和剩余内存；无崩溃或持续性卡死 |
| 反复切换 | 建议启动与退出同一游戏 5 次，无无法返回菜单、按键残留或持续内存下降 |
| 原型边界 | 测试输入和真实按键的结果分别记录；临时输入通过不算实体按键通过；本轮通过不代表存档或续航已通过 |

原型通过后，再在 `test-plan.md` 中根据实测基线确定具体速度、延迟和续航指标；游戏自身的模拟速度与屏幕刷新帧率分别记录。

## 现在开始的具体工作

1. **硬件立即开始**：登记 BaseBoard 丝印与连接器观察方向，记录主机配合尺寸；画出方向键、A／B、Start／Select 的纸面布局，留出菜单操作方式。先做资源表和按键原型，再确定 PCB。
2. **软件立即开始**：确认本机 ESP-IDF 安装位置并加载环境，固定可构建的 Mosaico BSP 基准，建立显示、声音和输入诊断入口。随后接入测试游戏；测试输入让软件工作不依赖控制板到货。
3. **首次联调前合并信息**：将已核对的电气定义、实际输入方案和软件逻辑映射互相链接；以实体按键控制测试游戏作为双方的第一次共同验收。

初查时会话没有加载 ESP-IDF；现已完成固定版本安装、激活和两种诊断配置的编译，见 [验证记录](../../firmware/game-console/test-records/2026-10-19-build.md)。下一步从“确认环境”推进到上板诊断，硬件同步核对接口配合和按键布局；游戏控制与实机验收仍未执行。
