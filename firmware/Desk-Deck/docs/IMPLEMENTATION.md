# 技术路线与分阶段验收

2026-10-25 已增加独立的 0.1.0-dev 固件，完成构建、官方安装、Windows 双 CDC + HID 枚举、24 次显示组合与重启检查。具体范围见 [实机记录](HARDWARE-TEST-2026-10-25.md)。以下保留分阶段目标，不能将所有计划项当作已验收能力。

## G0：先验证 USB，而后移植完整界面

官方 ESP-USB 文档提供 HID/CDC 与复合设备支持，但这不等于当前 Mosaico 应用可直接增加 HID。

本地预检基于 `project.json` 中的候选版本。Iris 源码 `ESP-Iris/components/esp_iris/src/esp_iris_transport_usb.c` 当前自行提供配置描述符，描述符长度/接口数按两个 CDC 计算，并将其交给 TinyUSB。官方应用通道要求 CDC0 日志、CDC1 数据。因此**仅打开 HID 的 Kconfig 选项不足以完成集成**。

验证步骤：

1. Desk-Deck 独立获取固定版本 SDK/BSP/utils，核对依赖许可与锁定提交；不引用其他应用的 build-deps。
2. 清点当前设备、配置、接口与端点描述符，分别核对所用控制器的高速/全速能力和端点预算。
3. 检查官方是否提供合并描述符/类驱动扩展入口。只保留一处 USB 驱动与描述符所有者，禁止另装一套 TinyUSB 与 Iris 抢占控制器。
4. 构建最小验证应用：一个键盘 HID、一个 Consumer Control 报告与官方 CDC 通道共存。先固定界面，再接 IMU。
5. Windows 枚举、标准键盘输入、媒体键、Iris 状态/日志/恢复通道全部验证通过才继续。
6. 若无安全扩展点，单独评估上游适配层或需要电脑助手的方案，记录影响；不能默默移除官方恢复/调试通道并宣称即插即用完成。

2026-10-23 只做了只读预检；2026-10-25 开始实机调试。描述符合并采用本项目链接器包装，不修改固定依赖，具体结构见 [构建说明](BUILD.md)。独立工程目录不会在设备上保留两套运行中的应用。

## 模块边界

```text
触摸 / IMU / USB 状态
          ↓
  输入归一化与去抖 → UI 状态（场景 / 弹层 / 锁定）
          ↓                 ↓
  动作白名单与就绪检查    局部重绘 / 振动反馈
          ↓
  单次 HID 报告 → 全键释放

电脑配置页 → 官方 RPC 适配层 → 配置校验 → 原子保存 → UI 更新
```

- `ui`：只管理显示、触摸意图和反馈，不能直接读写 NVS 或阻塞 USB。
- `input`：IMU 稳定窗口、朝向映射、触摸移动取消、长按消耗单击、锁定。
- `actions`：只接受已校验的键盘/Consumer 动作；USB 就绪才提交。队列应有界，断连清空，不重放。
- `usb`：统一管理 HID 和官方通道，保证按下与释放；断连/挂起/模式切换时丢弃未提交输入，恢复后先清零报告。
- `config`：schema 版本、原子提交、回读校验、默认配置恢复，命名空间 `deskdeck`。
- `platform`：沿官方 BSP 管理显示/触摸/IMU/振动/电源；使用已经验证的驱动时序，不手工改显示降频时序。

首个调试版集中在 `main/main.c` 和 `main/usb_hid.c`，页面事件与硬件循环通过显示锁或原子变量同步。后续按实际复杂度拆分，不提前创建占位驱动。

## 配置约束

`configs/default-profiles.json` 同时用于原型和编译期默认动作生成。调试版没有设备端配置导入器。G3 固件加载器必须验证 schemaVersion=1、product=Desk-Deck、四个唯一场景 ID、每场景六个唯一按键 ID、支持的朝向、名称长度及主题值；未知字段按协议定义处理。

键盘动作限制为零或多个不同修饰键（CTRL/SHIFT/ALT/GUI）加一个普通键；Consumer 动作限制为枚举白名单。禁止任意脚本、终端命令或隐式连续宏。参考 usage：上一曲 0xB6、下一曲 0xB5、播放/暂停 0xCD、静音 0xE2、音量加 0xE9、音量减 0xEA（Consumer Page 0x0C）；实际描述符与主机行为仍要核验。

写入采用双槽或临时记录+版本指针，完成校验后切换有效版本；失败不覆盖上一份配置。电脑侧不以“请求已发送”冒充“保存成功”，必须回读确认。正式 NVS 结构与导入兼容测试在 G3 确定。

## 实施与验收顺序

| 阶段 | 产物 | 必须通过的检查 |
| --- | --- | --- |
| G0 USB 可行性 | 最小设备应用、描述符记录、固定依赖 | HID + 官方通道、插拔、恢复路径 |
| G1 六键首页 | 真实 480×480 显示、按键反馈 | 所有 24 个默认动作、短按一次、滑出取消、无卡键 |
| G2 场景与设置 | 四向映射、滑动、锁定、设置 | 翻转只切页；长按不误发；设置随屏旋转且保留草稿；取消回滚 |
| G3 配置工具 | 电脑页面、RPC、持久化 | 参数越界/未知动作拒绝；断电保留有效配置；导入导出回读一致 |
| G4 稳定性 | 测试记录、资源/功耗测量 | 8 小时运行、100 次插拔/挂起恢复、1000 次触摸与切页组合、无重启或卡键 |
| G5 发布准备 | 使用说明、固件安装包、源码和许可证 | 真实截图、版本一致、恢复流程、无密钥或本机路径 |

不把阶段表当作工期承诺；G0 的 USB 集成难度决定后续工作量。

## 性能与功耗

按需刷新与短动效是默认策略。主循环不能被长日志、存储或 USB 等待阻塞；显示任务、USB 任务和姿态事件隔离。测量触控反馈延迟、HID 入队延迟、长任务耗时、堆高水位和空闲时间后，再决定是否降低时钟或启用休眠。

USB 主机挂起、普通静置、主动操作、显示亮度改变分别记录供电电压/电流；不以充电混合读数推算电池续航。本轮无功耗或温升改进数据，不声明续航目标已达成。屏幕休眠和唤醒只在确认首触不误发、USB 不丢输入后加入。

## 隔离清单

- 软件目录 `firmware/Desk-Deck`，硬件目录 `hardware/Desk-Deck`，独立工作区。
- `project.json` 记录固定依赖，不借用 Time-Tick 的本机路径、构建目录或官方项目标识。
- 未来自身 `build-*`、`build-deps` 和本机配置按仓库规则忽略；固件/原始素材/协议/测试记录自身管理。
- 分区方案以官方规范为准；不整片擦除、不复用 Time-Tick 宠物/网络/设置命名空间。
- 实机安装通过官方入口完成，恢复分区保留；需要恢复其他应用时使用其已验证安装包。
