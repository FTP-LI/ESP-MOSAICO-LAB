# Time-Tick V1.0 — 软件

ESP-Mosaico CoreBoard V1.2 / ESP32-S31 的翻转计时器项目。交互参考时间小方 TK3，加入可配置方向、正放时钟天气和屏幕自动旋转。项目名称为 **Time-Tick V1.0**，应用构建名为 `time_tick`，开发版本由 [version.txt](version.txt)提供，当前 `0.1.1`。

已实现以翻转计时为主体的独立倒计时页、全屏天气时钟、七页首次引导、双语界面及可选桌宠陪伴，并保留 Mosaico Ideas 发布框架。当前只保留呆猫：54帧涵盖待机、双向行走、照料、庆祝、睡眠及天气姿态；旧三宠已归档，不进入固件，不增加照料负担。PC 与固件共用 LVGL 和养成逻辑；已通过官方系统更新包装入实机，确认 Wi-Fi 与真实天气可用，卡顿修复与待验项见 [实机验证记录](test-records/2026-10-21-device.md)。尚未完成整机验收或网站发布。硬件配套见 [Time-Tick 硬件](../../hardware/Time-Tick%20V1.0/README.md)。

**版本范围：语音助手已归档，当前V1.0不加入；计划下一版本接回。** 源码、模型、详细教程及恢复步骤见[语音助手归档](archive/voice-assistant/README.md)。

**主题可选日间、夜间、自动。** 在“设置 → 系统 → 显示 → 主题与时段”切换；日间/夜间固定配色，自动模式用小时、分钟滚轮设定“夜间开始”和“日间恢复”，默认20:00–次日05:00，支持跨午夜。选项即时预览，保存后断电保留；返回取消本页修改，之后在父页面保存也不会带回已取消的主题。自动模式的两个时间不能相同。手动模式不需要联网校时；自动模式使用设备当地时间，时间未有效同步时保留当前配色。界面、天气光照及桌宠受光一起遵循主题，但时钟仍显示真实时间。详情见[可配置主题验证](test-records/2026-10-21-theme-settings.md)。

## Vibe Mode 0.2 迁移

0.1.1 使用 Recovery ABI 2 与双 USB CDC 通道，已在 Vibe Mode 0.2.1 上通过完整安装的首次启动、健康确认、正常重启与 60 次旋转/亮度切换检查。`main/platform/sdk_compat.c` 在时钟树初始化后恢复 PVT 所需的 REF160M 时钟门，解决旧基础固件暖启动到新 SDK 时的 Wi-Fi 初始化卡死；不增加运行期时钟引用、不关闭动态调频。完整证据与测试边界见 [迁移验证记录](test-records/2026-10-22-vibe-02.md)。

## 电量与运行优化

主页右上角显示 BQ27220 估算电量，点击电量或进入“设置 → 系统 → 电量与省电”可查看充电/放电状态、电压和带正负号的电池电流。每10秒采样；失败显示“电量暂不可用”，无电池单独提示，不用电压猜百分比，也不将零电流直接认作USB供电。

用户确认原装电池为68mAh；实机电量计此前仍是3000mAh默认参数。检测到容量不符时，后台仅在充电且电压至少3.5V时修正RAM中的设计容量、初始满充容量及近满充容量，读回验证后重新封存；每次启动最多尝试一次。容量匹配时保留学习结果，不改OTP、充电器、电压/电流校准或电芯曲线；不匹配期间隐藏百分比。此修正不等于电芯标定，实际续航、SOC精度与之前自行断电的原因仍需验证。

电池供电时降低天气特效与动作刷新频率；闲置60秒后亮度最高40%，低于等于15%电量时最高20%，始终不高于用户设置。触摸、翻转、设置页面、到时提醒会恢复用户亮度。计时/IMU继续工作，不进入会漏掉翻转或闹钟的深睡。天气保留15分钟成功刷新间隔，失败间隔1分钟；Wi-Fi失败重试逐步退避至5分钟，认证失败等待用户修正或重试。显示/声音设置改变不会重新请求同地点天气。

亮度和旋转命令由显示任务串行执行，避免与QSPI画面传输并发。主循环与界面分别受15秒看门狗监测，异常时进入已有崩溃记录/恢复流程；这不能替代长时间稳定性验证。

“设置 → 系统 → 显示”拖动亮度滑块即可预览，不必先保存。点击显示页的“保存”才写入新亮度；点击“返回”同时恢复已保存亮度并撤销亮度草稿，之后在上一级点“保存”不会重新保存已撤销的亮度。首次引导的显示页同样支持预览，其“上一步／下一步”保留引导草稿；闹钟打断时优先采用正常提醒亮度，结束后恢复草稿预览。滑动不逐次写入NVS，面板命令仍由显示任务合并、串行发送。

亮度控件使用独立76像素高的行，轨道高20像素、拖柄直径44像素，上下扩展后的触控带高64像素；可以点击轨道定位，再拖动微调。扩展区域与时区选择框分开。

界面仅在值变化时更新文字和样式；IMU/计时仍独立运行，状态快照以100ms间隔投递，LVGL任务每40ms取最新值。QSPI保持单帧缓冲、TE同步及显示命令串行，DMA最大分块由8行调为64行，减少事务开销。天气和呆猫的动画内容与原有供电分级保留。

本轮新增空闲30秒的装饰动画降频（USB/电池均适用），音频线程只处理铃声与提示音，空闲时阻塞等待消息；触摸、翻转、设置及提醒保持响应。发热分析、后续优化顺序和对照方法见 [系统优化说明](docs/SYSTEM_OPTIMIZATION.md)。实际温升与电池续航仍待同条件测量。

续航第二轮：CPU任务活跃上限保持320MHz、空闲动态降频至40MHz，不启用自动轻睡；绘制到屏幕DMA实际完成期间保持CPU/MEM频率稳定，音频关闭后停掉未使用I2S通道。清理空天气图层和气泡重复布局，静置30秒后天气装饰最多每秒主动刷新一次，保留桌宠动作和操作响应。首次无显示频率保护的候选出现花屏，已撤回；显示复测及功耗证据见[第二轮验证记录](test-records/2026-10-21-power-runtime.md)。增加拔USB期间的RAM平均电流统计，重连可读取；以平均≤68mA为一小时的理论门槛，实际达标需完整放电验证。

详细资源和实测数据见 [呆猫与电量记录](test-records/2026-10-21-daimao-power.md)及[性能与容量修正记录](test-records/2026-10-21-performance-battery.md)。

续航第三轮启用SDK加密时钟按需开关，IMU每轮一次读取加速度与角速度，保留原有采样频率和显示整帧保护。用户10%/100%亮度电流来自电量设置页，不能直接代表天气桌宠首页续航；本轮实测状态继续记录在[续航优化记录](test-records/2026-10-21-power-runtime.md)。

## 交互约定

电脑界面预览见 [PC 预览说明](pc/README.md)：在本目录的 VS Code 中选择 **Time-Tick: 电脑预览（GDB）** 后按 F5，或运行 **Time-Tick: 启动电脑预览** 任务。模拟控制台、方向、天气、晃动和校准按钮均为中文；产品界面仍支持中英切换。复用同一份 LVGL 界面与计时核心，预览无需烧录。

用户已确认：**正放暂停并显示时钟天气；翻到定时方向后，重新开始该方向预设时间**。同一方向保持不动不会反复重置。另提供“正放后台继续”“正放暂停、原方向续计”两种可选模式。

| 姿态 | 默认行为 | 可修改范围 |
| --- | --- | --- |
| 正放 Home | 时钟、日期、天气；暂停当前计时 | 正放计时策略 |
| 顺时针右转 90° Right | 5 分钟 | 0–86400 秒 |
| 倒置 Upside down | 10 分钟 | 0–86400 秒 |
| 左转 90° Left | 25 分钟 | 0–86400 秒 |
| 屏幕朝上平放 / Flat | 保留平放前屏幕角度及当前计时状态，不启动或重置计时 | 不提供预设 |
| 屏幕朝下 | 不触发新计时、不改变屏幕角度 | 不提供预设 |

有效姿态仍包括四个竖放朝向及屏幕朝上平放。正放用于时钟，只有右转、倒置、左转三个方向可设置倒计时。朝上平放和屏幕朝下不改变当前计时状态，正在运行的计时仍按原截止时间推进；平放后回到原计时方向也不重新开始。旧配置中的平放时长在加载时清零，下次保存写回，其他时长、网络与校准保留。

在“设置 → 计时”先选择方向，再上下滑动“小时／分钟／秒”三个滚轮，松手自动对齐；也可点相邻数字或5/15/25/60分钟快捷键。整页固定，滑动不会带走方向和保存按钮。最长24小时，选择24小时自动将分秒归零；启用时至少1秒，独立开关可关闭该方向。切换方向保留本次草稿，点保存后生效，直接返回放弃修改。“正放后的处理方式”单独展开设置。内部0秒表示禁用该方向，翻入禁用的右转/倒置/左转方向会停止当前计时。平放法向由校准坐标系推导，实机首测仍须确认屏幕朝上/朝下对应正确。初始数值是本项目预设，不是 TK3 参数复刻。

定时方向显示独立的田园主题圆形表盘，包含大数字、剩余进度环、方向预设与状态胶囊，保留全屏天气背景，以随主题切换的渐变衬托数字，隐藏桌宠和主页控件。运行、暂停、到时分别使用绿色、暖棕色和金色；最长24小时自动调整字号。到时显示暖色提醒，按“到时提醒”设置重复响铃与间歇振动。停止后保留该方向的计时页，可轻点圆盘重新启动，或翻到其他方向。倒计时使用单调时钟，联网校时不会改变剩余时长。正在运行的倒计时不跨断电保存，方向预设、校准和联网设置保存在 NVS。

**圆盘操作：轻点开始／暂停／继续，长按0.8秒停止并重置。** 圆盘下方不再显示独立操作按钮，改为当前状态的中英文提示。数字、进度环和外圈刻度均可触摸，按下显示描边；触发前滑出圆盘可取消。停止后回显当前方向的完整预设时长，再轻点即可重新开始；禁用方向不启动计时。到时轻点或长按均只关闭提醒，不立即开始下一次计时；翻转结束提醒的规则保持不变。

手动轻点开始采用当前已显示方向的预设，不要求按压时重新保持静止，避免触摸造成轻晃后丢失操作。自动翻转仍须稳定450毫秒；轻点启动后重新稳定在同一方向不会再次重置倒计时。

桌宠随昼夜调整受光：夜间降低亮度并加入冷色环境光，晨昏轻微暖色，切换时650毫秒平滑过渡。待机、走路、睡觉和互动共用同一受光样式；不降低透明度或修改屏幕亮度。

## 首次使用

1. 首次启动选择简体中文或 English，然后进入网络页自动扫描。上下滑动选择 Wi-Fi，在带数字行的屏幕键盘输入密码；开放网络无需密码。可选“离线继续”，以后从设置联网。
2. 后续依次是**伙伴 → 显示 → 到时提醒 → 天气 → 方向校准**，每项单独一页，无需向下寻找隐藏选项。点呆猫图片或名字播放约2.7秒的玩球动作。显示页调整亮度与UTC时区；到时提醒页调整铃声、提醒时长、音量与振动。天气页支持联网估算当前位置、城市搜索候选和常用城市选择；经纬度放在高级入口，默认时区UTC+8。
3. 按外壳的正放姿态稳定放置，点击“记录正放方向”；面对屏幕顺时针旋转 90°，稳定后点击“记录右转方向”。也可先跳过校准。
4. 完成引导并保存后进入小院：伙伴自主散步、停留与打盹；点草地召唤，点伙伴摸头。点右下角“陪伴”进入独立伙伴页，喂食、玩耍、洗澡、休息，并查看专注次数、累计分钟、亲密度和六项专注成就。状态不会随时间下降，互动不扣其他状态，成就永久保留，长期不照料不会受罚。翻转会直接退出养成并启动计时。旧三宠存档自动迁移，呆猫继承经验最高伙伴的进度，专注成就保留，详见 [养成规则](docs/PET_CARE.md)。中英文和网络均可在设置中调整。
5. 在计时设置中修改方向预设；逐方向验证计时和触摸。画面方向相反时启用“反转屏幕旋转方向”。

普通设置操作期间屏幕和触摸继续随四个竖放方向旋转，保留未保存内容；只暂停翻转触发的新计时或预设切换，已启动的计时继续按原状态运行。养成页不会冻结翻转；到时提醒优先于养成及设置，覆盖设置时也可翻转结束提醒，随后返回原设置表单并保留草稿。校准需要加速度接近 1g、角速度较小且稳定至少 450 ms；无有效 IMU 数据时保持计时状态。屏幕和触摸同步切换 0°/90°/180°/270°。平放时重力不能确定屏幕平面内的朝向，因此保持上一朝向。

## 声音、振动与对话入口

在 **设置 → 系统 → 到时提醒** 配置铃声，首次引导也有独立的到时提醒页。可选九款：**清亮钟声、电子闹铃、轻快旋律、叮咚门铃、小院风铃、木琴跳音、晨光唤醒、游戏过关、节拍提醒**。展开铃声列表后上下滑动选择，可直接试听。新增音效使用不同音符、节律、谐波和衰减，不加载录音文件。独立调整铃声音量（0–80%）与提醒时长（15/30/60秒），分别开关响铃和振动。默认清亮钟声、65%音量、30秒；每3秒播放一段旋律，并短振两次。日常操作的轻提示音仍沿用原音量（默认25%），关闭它不会关闭闹钟。

闹铃使用独立增益曲线；原有三款保持已验证的增强波形，相同音量设置下数字信号链较初版提高约15 dB。九款均保留波形余量与10毫秒淡入淡出。界面的百分比是可调档位，不代表声压；实际响度以设备试听为准。升级保留已保存的铃声、音量、静音和提醒时长，日常提示音不使用此增益。

电子闹铃使用1200/1500 Hz提示音。音符间隔持续写入静音采样，结尾等待淡出样本离开DMA再关闭功放。若仍偏小或有杂音，日志中的`output check`会读回ES8311音量、静音、声道位宽及功放使能输出，`render_max`记录每10毫秒音频块的最大合成耗时；这些检查不能代替实际扬声器试听。

排查“只有嗡声”时，应关闭振动再试听。开发诊断也可经官方Iris gateway调用私有RPC `0x5454/2`，负载`speaker`：65%轻快旋律、3秒、强制无振动、不保存配置；负载`stop`结束测试。方法仅用于开发检查，复用正常播放路径，操作和实际听感记录于`test-records/2026-10-21-alarm.md`。

点“试听 3 秒”立即使用当前页面的草稿，无需先保存；“停止试听”、离开声音页、保存都会结束试听。点“保存”后设置才写入设备。铃声音量为0或取消“响铃”时不发声，振动仍由其开关决定。到时提醒超过所选时长自动停止发声和振动，完成画面保留到用户关闭。音频在独立任务播放，主循环不等待整段铃声；取消时会清除队列，并在10毫秒音频分块之间检查停止请求。

**到时后翻转一次只关闭提醒，再翻一次才开始新计时。** 从到时姿态转到另一稳定朝向（正放、侧放、朝上/朝下平放都可）后，同时结束声音、振动与完成画面；不会立即启动该朝向的预设，保持不动也不会重新响铃。再次翻到启用的计时方向才开始新一段，或点“开始”。使用原有约450毫秒稳定判定，快速晃动、短暂倾斜及IMU读取失败不会误关闭。运行中/暂停时的翻转规则保持不变；设置内的3秒试听仍由停止按钮或超时结束。

设置schema 6兼容旧schema 1/2/3/4/5，保留网络、位置、方向、校准和声音配置，移除已取消的平放/朝下预设，并为旧配置补上自动主题与默认20:00–05:00时段。旧版已关闭声音的设备迁移后仍关闭响铃，可在到时提醒页开启。伙伴schema 3兼容旧schema 1/2并迁移到呆猫。

语音助手已移至[下一版本归档](archive/voice-assistant/README.md)。当前固件和电脑预览均移除入口、配置页与模拟唤醒；不加载模型、不运行语音网络任务、不采集麦克风。原有配置教程和接回步骤保留在归档中。

## 时间与天气

网络任务独立于计时与绘制。Wi-Fi 支持异步扫描、信号排序、SSID 去重与手动隐藏网络。连接尝试最多等待约 20 秒，失败后约 30 秒重试，也可修改密码立即重试；SNTP 校时后通过验证证书的 HTTPS 获取天气。天气成功后约 15 分钟刷新，失败约 60 秒重试；无网时显示缓存标记，首次无数据时显示连接状态。

内置 [Open-Meteo Forecast API](https://open-meteo.com/en/docs)，当前个人非商业使用无需填写密钥；商业使用按[官方许可与套餐](https://open-meteo.com/en/pricing)处理。首次引导和“设置 → 系统 → 天气”现在提供：

1. **联网定位当前位置**：连接Wi-Fi后，通过 [ipwho.is](https://ipwhois.io/documentation) 按网络出口IP估算地区，显示结果供你点选确认。代理、运营商出口可能导致偏差，不准确时改用搜索。
2. **搜索城市**：输入拼音或英文，例如 `hangzhou`；[Geocoding API](https://open-meteo.com/en/docs/geocoding-api) 返回最多5个候选，展示城市、省份/地区和国家，点选所需地点。接口也接受中文名称，屏幕键盘目前仍为字母输入。
3. **常用城市**：点北京、上海、杭州等12个快捷入口，联网查询后确认，无需打字。

点选只修改当前草稿；设置页点“保存”，首次引导走到最后点“进入小院”后才写入设备NVS。退出或取消不会保存新地点，过期查询结果也不会自动覆盖选择。地点坐标随候选一起保存，日常不需要知道经纬度。

已有坐标可展开“高级：手动经纬度”，使用WGS84纬度−90～90、经度−180～180，保留六位小数；不要直接填写GCJ-02/BD-09坐标。自动定位和城市检索无需API Key，仅在主动点击时发起请求；定位服务会看到请求的公网IP，搜索服务会收到查询词。详细验证见 [地点选择记录](test-records/2026-10-20-location.md)。

经纬度能准确指定请求地点，但天气仍来自模型网格，不能等同于小区级实测。界面保留来源和缓存标记，显示温度、相对湿度、天气情况；PC地点查询使用电脑真实网络，天气数值仍为明确标注的示例。当前没有GPS或手机地图选点。按天气代码切换晴、多云、雨、雪、雾、雷雨六种全屏背景，采用650ms交叉淡入，天气粒子与昼夜光照用800ms淡入。按设备本地时间切换清晨/白天/黄昏/夜晚，按月份与坐标所在半球选择季节；系统主题时段可自定义；清晨/黄昏仍采用固定时间，不是天文日出日落，尚无预报分页。素材替换见 [天气背景 README](assets/weather/README.md)。设置变更后丢弃旧请求结果。离线时翻转计时可用，断电后时钟需重新联网校准。

界面支持中英切换、抗锯齿字体和字母/数字/符号屏幕键盘；离线 RTC、中文输入法、半小时时区/DST尚未实现；动态CPU调频已启用，自动轻睡保持关闭以保证显示与翻转可靠，电池续航仍待实测。设置的 Wi-Fi 信息仅保存在设备 NVS，不写入源码或日志；目前没有启用 NVS 加密。

在 VS Code 中直接打开本目录，使用官方 **ESP-IDF 扩展**。SDK 固定为 ESP-IDF 6.2 开发版 `1c42e514c90ae621af33bde3b6ad3dac22edcbfd`；本机路径 `C:\Espressif\esp-idf-v6.2-mosaico\esp-idf`，目标 `esp32s31`。使用 `ESP-IDF: Build Your Project`。扩展提供的 ESP-IDF 终端中等价命令为：

```powershell
idf.py --preview --no-ccache --no-configdep -B build-idf62-v02 build
idf.py --preview --no-ccache --no-configdep -B build-idf62-v02 system-update-bundle
```

本机工作区配置位于被 Git 忽略的 `.vscode/settings.json`，新版生成配置位于 `build-idf62-v02/sdkconfig`。本机 EIM 的环境仍引用 GCC 15.2，当前项目通过扩展的 `idf.customExtraVars.CMAKE_PROGRAM_PATH` 指向已安装的 `C:\Espressif\tools\tools\riscv32-esp-elf\esp-16.1.0_20260609\riscv32-esp-elf\bin`，并设置匹配的 `ESP_ROM_ELF_DIR`；新构建目录避开旧编译器缓存。使用终端时同样确保这两个环境变量正确，或选择已完整修正工具链的官方 SDK 环境。

首次在应用目录运行 `python tools/prepare_dependencies.py`，获取固定提交的官方 Vibe Mode 0.2 / Iris 依赖；再配置 ESP-Iris 打包 Python 环境（`ESP_IRIS_PYTHON`）。项目根 `mosaico.py` 只转发该依赖的官方 CLI。源字体和发布资源的准备见 [发布说明](publish/README.md)。[dependencies.lock](dependencies.lock)由本工程组件管理器实际解析生成。

16 MiB 分区保留 Vibe 固定区域：`vibe_mode/app/test` 位于 0x20000，正常应用 `main_app/app/ota_0` 位于 0x210000。旧版设备须先通过本项目 `mosaico.py recover` 迁移基础固件；不能跨代 OTA。日常通过 `mosaico.py iris system-update --bundle build-idf62-v02/time_tick-system-update.irisfw` 安装。新集成支持匹配布局下的原生烧录，但本项目设备操作统一使用官方 CLI，先核对完整写入范围；不覆盖用户 NVS。迁移结果见 [0.2 验证记录](test-records/2026-10-22-vibe-02.md)。

最新界面与养成实现见 [界面规范](docs/UI_STYLE.md) 和 [验证记录](test-records/2026-10-20-scene-voice.md)。PC 预览在 VS Code F5 中运行；扫描列表、网络连接与天气为模拟数据，系统设置只保留当前会话，桌宠进度单独保存在 `build-pc/preview_pet_save.bin`，重启可恢复。控制窗口可切换正常/空列表/扫描失败；模拟密码 `wrongpass` 用于验证错误提示。当前 EIM 的 configdep 0.2.3 对工程路径中的空格处理有误，上述终端命令显式关闭可选构建加速器；Ninja 的普通增量编译仍然保留。不要因 SDK 的通用 flash 提示而覆盖保留的 Vibe Mode 分区。

PC 构建包含计时、设置、闹铃、养成、动画、电量、天气、场景、地点九组核心测试，以及八组界面测试，共17项；覆盖模拟IMU到计时页面、七页引导、经纬度验证、联网/断线状态刷新、亮度与主题预览、保存/撤销及昼夜时段边界。先按 [电脑启动流程](pc/README.md)完成构建，再运行：

```powershell
ctest --test-dir build-pc --output-on-failure
python publish/validate.py
```

保留有效 `build-pc/`、新版 `build-idf62-v02/`、旧版 `build-idf62/` 与必要依赖以支持增量编译。旧 `build/`、`build-host/` 和重复单帧导出已清理；桌宠存档位于 `build-pc/preview_pet_save.bin`，删除构建目录前须单独备份。
