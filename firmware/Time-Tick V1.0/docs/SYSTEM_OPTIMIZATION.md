# Time-Tick V1.0：发热与运行优化

更新：2026-10-21。用户确认“拔掉USB、用电池运行也明显发热”，因此要同时排查持续运行负载、电源转换与电池供电路径，不能只归因于充电器。

## 目前已确认的事实

| 项目 | 当前状态 | 判断范围 |
| --- | --- | --- |
| 长时间不操作的首页 | 优化前约119次重绘/10秒，平均每帧81.8ms | 包含绘制、TE及传输等待，不等同于CPU占用率 |
| CPU | 第二轮配置320MHz活跃上限、40MHz空闲下限，驱动持锁时按需升频 | 不启用自动轻睡，不能把频率范围直接换算成省电比例 |

| 电量计温度 | 本次优化前读到3092个0.1K，约36.1°C | 是电量计温度寄存器读数，不是CPU结温或外壳实测温度 |

插USB时电池电流接近0mA，不能解释为整机没有消耗电力：系统可能主要由USB供电。现在也没有USB输入功率的实时测量，不能据此计算省电百分比或续航。

## 本轮优化与验证边界

### 装饰动画按活动状态调度

连续30秒没有触摸或改变设备朝向后，桌宠/小院更新间隔为100ms，天气装饰更新间隔由第一轮300ms改为1000ms；插USB和电池供电都适用。此间隔只控制装饰请求刷新的频率，其余界面更新也可能重绘这些图层，没有移除天气效果、桌宠动作或改变计时速度。雨、雾下没有实际内容的桌宠前景图层不再每100ms无条件请求整屏刷新；有效天气小装饰按天气刷新节奏更新。

触摸、翻转后恢复原活跃策略。设置页面和到时提醒保持活跃策略。显示任务仍接收最新状态，计时和IMU仍以20ms周期运行；待机时钟和倒计时数字仍按自身变化更新。它是减少无人操作时的装饰负载，不是把整个系统锁成低帧率。

电池原有亮度规则保持：闲置60秒亮度上限40%，电量≤15%时上限20%，均不高于用户设置；触摸/翻转和交互页面恢复。不自动更改用户保存的亮度。

### 音频任务空闲时等待事件

语音归档后，音频线程通过 `portMAX_DELAY` 阻塞等待铃声/提示音队列，不再轮询语音状态。声音请求进入队列可立即唤醒线程；已有PCM生成、播放和取消流程保持不变。

到时提醒继续优先，翻转取消仍通过原有取消信号和分块检查。此前“游戏过关”的查表合成修复保留。

### 空闲降频与音频通道回收

第二轮开启ESP-IDF动态频率调节，CPU活跃上限仍为320MHz，空闲下限40MHz。RTOS就绪任务及驱动电源锁决定实际频率；不启用自动轻睡，不改变20ms IMU/计时周期、触摸读取与响铃采样率。依据：[ESP32-S31电源管理文档](https://docs.espressif.com/projects/esp-idf/en/latest/esp32s31/api-reference/system/power_management.html)及工程固定的SDK驱动源码。

首次DFS候选在旋转/亮度压力测试中出现实物花屏，已撤回；用户确认回退后恢复正常。内部帧缓冲截图正常，不能据此判断面板正常。固定SDK的S31 SPI驱动仅持APB_MAX锁，未覆盖PSRAM所需的CPU/MEM频率；新版增加整帧CPU_MAX保护，从绘制开始直到TE同步的DMA实际结束才释放。非同步传输模式则保持锁到显示删除，不能把提交DMA当作传输完成。修订版完成60次旋转/亮度测试，用户确认“画面正常”；长期稳定性仍需持续使用验证。保护会减少可降频时间，不能沿用未保护版本的省电预期。

BSP初始化时同时启动I2S收发DMA，但关闭扬声器只会关闭发送通道；未使用的接收通道可能持续运行。现在仅由同一个音频线程，在关闭编解码器流后检查并停用剩余通道。播放、收音、唤醒检测期间不关通道，不切断编解码器供电、不更换已验收的音量/音色。

### 加密时钟与IMU读取

第三轮发现已有构建配置保留了 `CONFIG_ESP_CRYPTO_CLK_ON_DEMAND=n`，即使随后打开PM，旧值也未自动更新。改为y后，SDK在加密任务结束时按引用计数关闭加密时钟，并释放PLL_F240M使用权；使用同一时钟源的其他外设仍由SDK时钟树管理。此为S31在PM启用时的默认建议，依据固定SDK的 `components/esp_security/Kconfig` 与 `src/esp32s31/esp_crypto_clk.c`；没有直接关闭共享时钟，也没有关闭TLS校验。开关时钟有运算开销，实际天气HTTPS需在设备上复测。

IMU每20ms原先分别调用加速度、陀螺仪接口，而两个接口各自读取完整数据。现在合并为一次读取、转换同组两向量，减少重复I2C访问；100Hz传感器ODR、20ms姿态采样与450ms稳定判断保持。

### 第四轮：空闲系统节拍抑制（候选）

固定SDK在 `esp_pm/Kconfig` 提供 `PM_TICKLESS_IDLE_WAITI`，用于DFS开启、自动轻睡关闭时的空闲等待。应用保留1000Hz调度分辨率，启用 `FREERTOS_USE_TICKLESS_IDLE` 和 `PM_TICKLESS_IDLE_WAITI`，预计空闲至少3个tick时由SDK暂时屏蔽周期tick中断，等待外设中断或最早截止时间；唤醒后补齐RTOS时间。`light_sleep_enable=false` 保持，显示整帧CPU_MAX保护保持。工程未使用依赖每个tick调用的应用tick hook。

此项修改涉及调度，PC无法模拟ESP32内核；必须在设备上检查主循环间隔、触摸/翻转、响铃、USB重连、Wi-Fi与显示，并与固定亮度平均电流比较。不能把编译成功当作功耗或时序验收。暂不进一步降低装饰刷新率或改变桌宠活动行为；后续根据测量选择优化项。

候选已安装并通过健康检查；自动60次旋转/亮度切换完成，铃声生成无超时，普通空闲段主循环最大27–29ms。压力与主动诊断附近仍观察到60–93ms，因此不宣称严格20ms实时保证。用户已确认大滑块、画面、翻转和铃声正常，约85分钟后同一boot、无崩溃记录。回测210秒平均101.8mA包含翻转、倒计时和响铃，同时已进入夜景，不能直接与此前首页80.4mA比较；本段理论约40分钟，尚未达到一小时。完整证据见[续航记录](../test-records/2026-10-21-power-runtime.md)。

### 第五轮：去除夜间和倒计时的重复绘制

夜间晴/多云装饰被动画隐藏后，主页快照又每100ms将其显示，形成可见性反复切换；修复前实机夜间首页约126–129帧/10秒。统一两条路径的判定，使装饰保持正确状态。倒计时圆环则只在LVGL实际显示角度变化时更新，避免同角度的无效旋钮区域失效；数字、百分比和可见角度仍按原值更新。两处均有先失败后通过的回归，共6项相关检查通过；未减慢动画、输入、IMU或声音，也未移除显示保护。实机重绘和电池对照见续航记录。

安装后60次旋转/亮度自动检查完成；夜间首页连续5个10秒窗口降为25–64帧，主循环最大26–28ms，未见崩溃。重绘下降已得到日志支持，电池平均电流和温升改善尚待固定10%亮度的独立静置测试，不以重绘降幅代替续航计算。

### AI 使用建议

首次配置先用点击对话，确认云端和收音正常后再开启本地唤醒。若更看重发热和续航，可常用点击对话；不需要关闭整个助手。完整步骤见[AI配置教程](AI_SETUP.md)。

没有修改充电电流、电芯曲线或保存的亮度，也没有启用轻睡/深睡。实际温升是否降低，需要同条件观察，不能仅凭编译通过宣布解决。

## 一小时续航目标与测量

用户报告第一轮电池电流约−105mA，并进一步确认是刚打开电量设置时的活跃读数；不能把它当作首页自动调暗后的平均值。若持续保持105mA，原装68mAh的满充理论续航约39分钟，实际混合使用时长尚未测出。达到一小时要求平均放电电流不高于68mA，考虑容量偏差、截止电压和操作负载，建议把同条件静置目标放在60mA以内，再做完整放电验证。电池侧电流已包含整机供电损耗，无需再重复乘一个电源效率系数。

显示保护版的用户对照读数来自**电量设置页**：10%亮度约60–96mA、100%亮度约122–145mA（均为放电电流绝对值）。维持这些电流时，68mAh理论约42.5–68分钟、28.1–33.4分钟。最后记录到的连续有效放电段只有80秒，混合亮度平均86.5mA；既不是5–10分钟固定亮度首页基线，也不能据此推断新版低亮度必然达标。用户确认该轮显示、翻转和铃声均正常。

之后用户按10%亮度首页进行了约3分钟电池测试：RAM记录170秒有效连续采样，平均80.4mA、消耗3.801mAh；去掉首60秒后110秒平均79.9mA。68mAh理论约50.7分钟，距一小时理论门槛仍需降低约15%的平均电流；若以60mA留余量，需要约25%。设备未重启，已保存基线再进行下一版安装。该测试尚非整小时放电验收。

新版每10秒取样，以相邻有效电池电流做梯形积分，保留本次连续电池供电段的平均值和消耗容量，同时另算去除最初60秒的平均值。重新连接USB后保留上一段统计，下一次电池供电重新开始；重启会清除。无效读数、超过20秒的采样间断不插值，USB充电电流与模拟数据不计入。它是采样估计，不能替代精密功率仪或真实一小时运行测试。

调试读取通过官方gateway的私有RPC `0x5454/3`，payload为UTF-8 `power`（兼容性由本项目负责）。返回 `sampled_seconds`、`average_ma_x10`、`used_uah`、`settled_seconds`、`settled_ma_x10`、`sample_end_ms`，并把PM锁和频率驻留统计写入设备日志。没有有效时长时均值字段为0，不能解释为零耗电。先拔USB运行5–10分钟，再接回并等待一次电量采样后读取；不要重启。Wi-Fi刷新和闹铃所耗电量包含在对应采样段内。

## 下一阶段按这个顺序推进

| 优先级 | 工作 | 验证方法 |
| --- | --- | --- |
| 1 | 测量完整供电与热源 | 同亮度、同天气、同环境，分别测USB稳定供电和电池放电；USB功率表或串联电流测量配合外壳温度记录 |
| 2 | 进一步减少整屏重绘 | 优先缓存静态表盘与图层，分离时钟/桌宠/粒子更新；测活跃触摸延迟，不能只看FPS |
| 3 | 验证动态频率与按需外设回收 | 检查PM实际驻留时间与电池平均电流，检查QSPI、I2S、USB网关、Wi-Fi；保持自动轻睡关闭 |
| 4 | 按需管理外设 | 核对扬声器PA、麦克风、IMU采样和其他未使用器件的实际电源状态；优先停掉确定未使用的资源 |
| 5 | 改善AI链路效率 | 缩短空闲监听范围、评估回复流式播放和缓冲归属；保留闹钟抢占、网络超时与取消处理 |

显示目前使用整帧渲染，驱动在发送前原地交换RGB565字节；不能只把LVGL的FULL改成DIRECT，否则可能出现未重绘像素被重复交换的问题。双缓冲/异步传输需要一起管理DMA读取、旋转、截图和缓冲生命周期。

68mAh电池的实际续航、SOC准确度及先前自行掉电问题仍需充放电验证。容量字段修正不等于电芯模型已标定。

## 用户可重复的对照操作

亮度滑块现支持即时预览；对照测量时仍须点击保存，再返回被测页面。离开显示页会结束临时预览，不能把未保存的滑块值当作首页的实际亮度。

1. 关闭本地唤醒，选相同天气页面，把亮度固定在同一档。
2. 设备静置5分钟，确认闲置时仍有天气和桌宠、时间正常前进。
3. 触摸和翻转，确认亮度/交互恢复，启动短倒计时并检查响铃及两步翻转关闭。
4. 相同室温与摆放条件下，对比优化前后外壳同一位置温度。记录USB/电池状态；更换供电方式后不要立即把瞬时温度拿来比较。
5. 当前版本不包含语音助手，静置对照不需要再设置唤醒开关；下一版本恢复语音后再独立测量它的额外耗电。

优先记录“运行多久、供电方式、亮度、当前页面、唤醒是否打开、哪个部位发热”。若有温度计，提供同一位置的读数比单纯“烫/不烫”更容易定位。
