# 2026-10-20 桌宠养成与插画界面验证

## 本轮变更

主屏新增“养成”入口，独立照料页包含四种需求、亲密度、成长等级、喂食/玩耍/洗澡/休息与成长手账。猫、狗、小鸡各自保存进度。伙伴会自主散步、停留、开心、打盹，支持点地面召唤和摸头。

生成庭院与三种动物的透明姿态素材，替换原方块动物和代码拼接场景。主屏庭院 448×230、养成场景 448×190；统一轻色圆角界面，修正底部按钮贴边及手账页残留提示。美术原件、完整提示词与转换脚本在 `assets/pets/`。

## 自动检查

命令在 `firmware/Time-Tick V1.0` 执行：

```powershell
cmake --build build-pc --parallel 8
ctest --test-dir build-pc --output-on-failure
python publish/validate.py
```

最终 PC 构建通过，`-Wall -Wextra -Werror`。CTest **5/5**：

- `core`：方向、计时、暂停/恢复和旋转核心回归。
- `settings`：配置默认值、校验及旧配置兼容。
- `pet_model`：需求变化与上下限、冷却、睡眠恢复、自动醒来、成长上限、三种伙伴隔离、存档长度/版本/数值校验。
- `preview_smoke`：首次引导、Wi-Fi 列表/键盘/重试/取消、双语切换、保存失败；养成入口、自主移动与边界、照料保存失败回滚及重试、重复喂食保护、玩耍/清洁/休息/起床、成长手账、返回及计时回归。
- `preview_configured`：已完成引导的界面及同一养成/计时流程。

发布框架检查通过：元数据、受保护分区布局、版本 `0.1.0`。仍提示发布封面/截图、`.irisfw` 检查及实机验收待完成。

## 实际窗口

使用 VS Code 的 `Time-Tick: PC preview (GDB)` / F5 启动最终程序。观察并操作中文引导、主屏和养成页：

- 三种伙伴原生尺寸显示，庭院植被、池塘、农舍细节正常；主屏“养成”可进入独立页面。
- 猫猫自行移动；喂食后饱食度 70 → 95，经验 0 → 8，显示开心姿态及照料反馈。
- 手账显示喂食 1 次及“第一顿饭”成就。
- 关闭旧调试会话、重新编译和 F5 启动后，保留了猫猫进度。随后用户在预览中体验了其他伙伴；只读检查本地存档确认猫经验 8/喂食 1、狗经验 30/喂食 1/玩耍 1、小鸡经验 2，三种记录互不覆盖。
- 最终窗口观察到狗狗睡眠、精力恢复、“起床”按钮及爱心反馈。用户正在操作，因此保留其当前页面，没有重置演示存档。

PC 存档为 `build-pc/preview_pet_save.bin`，本轮实际产生 124 字节 schema 1 文件。PC 自动测试使用隔离的内存数据，不读写此文件。PC 网络、天气与 IMU 输入仍是模拟。

## ESP-IDF

使用项目固定的官方 ESP-IDF 6.2 / ESP32-S31 工具链，通过官方命令行进行最终增量构建：

```powershell
idf.py --preview --no-ccache --no-configdep -B build-idf62 build
```

- 最终构建成功，镜像 `build-idf62/time_tick.bin`。
- 大小：**3,923,888 字节**。
- SHA-256：`e0e97ff613be38d78469d1b653dc4f5b6853f10af05183d1af38afbecc9c04e2`。
- 本轮固件构建是官方 `idf.py` 命令行；PC 演示从 VS Code F5 启动，不混称为 ESP-IDF 扩展构建。
- SDK 对较小 `factory` 分区给出大小警告；应用目标仍为 `ota_0`，容量 `0xdf0000`，当前镜像可容纳。保留 Vibe factory，不按通用构建提示执行普通 flash。
