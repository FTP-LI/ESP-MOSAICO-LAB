# Time-Tick 实机联网与卡顿排查

设备：ESP-Mosaico CoreBoard V1.2 / ESP32-S31 rev0.0。ROM下载模式为COM87，应用/Recovery的ESP-Iris USB接口为COM88。日期：2026-10-20至2026-10-21（北京时间）。产品名Time-Tick V1.0，当前开发固件版本0.1.0。

## 构建与安装

- 官方ESP-IDF 6.2 Mosaico，提交`1c42e514c90ae621af33bde3b6ad3dac22edcbfd`，RISC-V GCC16.1；复用VS Code工程配置及`build-idf62`。
- 官方CMake目标`system-update-bundle`构建应用+分区表；修正项目VERSION参数与IDF项目宏不兼容导致release为空的问题。
- 官方ESP-Iris gateway执行Recovery协助更新，安装后验证新boot_id、ELF hash及healthy；不会以上传成功替代启动验证。
- 仅更新ota_0应用与相同布局的分区表，保留bootloader、Recovery和NVS。用户已输入的Wi-Fi在更新及重启后自动重连，密码不写源码、命令或本记录。
- BOOT模式时使用gateway `host.probe`调用官方esptool的`chip-id`和`hard-reset`恢复启动，不执行擦写。

## 已定位的问题与修改

1. 原显示配置队列深度10、每块8行RGB565，PSRAM图像先复制到内部DMA内存。联网后反复`spi transmit (queue) color failed: ESP_ERR_NO_MEM`与`Draw bitmap failed`，可造成黑屏/不再刷新。改为S31支持的PSRAM直接DMA、队列深度2。后续实机观察未再出现该错误。
2. 应用主循环每200ms尝试获取20ms的LVGL锁；整屏绘制/传输长时间占锁，实测约每50次刷新有38–44次失败。改为容量1的最新状态队列，由LVGL定时器处理；计时/IMU主循环不等待画面。尚未处理的旧快照可被覆盖，保证显示最新状态。
3. 网络页只显示泛化提示，扫描结果也不会随连接状态变化刷新。现在常显状态和网络名称，高亮已连接网络，并响应断线/重连。PC回归覆盖不改变扫描代数的连接状态切换。
4. 不变标签、服装/动作资源避免重复设置。天气场景每帧都重新混合大面积季节/昼夜渐变，改为稳定850ms后缓存RGB565背景；天气/时段变化时恢复原渲染完成650/800ms淡入，再重建缓存。每个已显示的小院最多增加460,800字节内存，分配失败保留原路径。动态雨雪/星光仍实时绘制。
5. LVGL固定核心1，降低对核心0计时/IMU循环的影响。诊断每10秒记录重绘数、平均/最大耗时、flush耗时、状态队列投递失败次数、循环最大间隔及可用内存。日志名`ui_miss`在队列版表示投递失败，不再表示获取界面锁失败。
6. 接入ESP-Iris按需截图；仅明确请求时复制全屏PSRAM缓冲，结束后释放。依赖当前单缓冲RGB565/TE整屏路径，其他布局明确返回不支持。
